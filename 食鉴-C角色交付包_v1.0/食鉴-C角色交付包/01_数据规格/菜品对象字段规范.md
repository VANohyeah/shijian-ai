# 菜品对象字段规范 v1.0（C · 数据侧）

> 本文件是 **A（AI/后端）、B（前端）、C（数据）三方共用契约**。
> 任何人要改字段，先改这份文件 + `vocab.json`，再由 C 统一回刷 `dishes.json`。
> 上一版方案文档里 4.1 节的示例 schema 保持不变，本文件只是把它落到可校验的粒度。

---

## 一、为什么必须是同一套字段

两个入口——**拍照识别（M1）** 与 **地域推荐（M3）**——最终都产出同一个 `dish` 对象。
健康评估（M2）只实现一遍，因此 M1 的视觉模型 prompt、C 的地域库、B 的菜品卡，三处字段必须逐字一致。

判定标准很简单：**把一条地域菜库记录扔给 M1 的输出解析器，不能报错；把 M1 的输出写进地域库，也不能报错。**

---

## 二、字段定义（11 个字段，全部必填）

| # | 字段 | 类型 | 必填 | 取值约束 | 说明 |
|---|---|---|---|---|---|
| 1 | `id` | string | ✅ | `dish_<city_id>_<两位序号>` | 全局唯一，发布后不可改 |
| 2 | `name` | string | ✅ | 2–12 字 | 中文菜名，用大众叫法，不用餐厅自造名 |
| 3 | `region` | string | ✅ | 必须等于该城市在 `vocab.json.cities` 里的 `region` | 菜系 |
| 4 | `city` | string | ✅ | 必须等于 `vocab.json.cities` 里的 `name` | 城市中文名 |
| 5 | `ingredients` | string[] | ✅ | 4–8 项，具体食材 | 写可采购的原料名，不写"秘制酱料" |
| 6 | `method` | string | ✅ | `vocab.methods` 中取值 | 主要烹饪方式 |
| 7 | `flavors` | string[] | ✅ | 1–3 项，取自 `vocab.flavors` | 口味 |
| 8 | `spicy_level` | int | ✅ | 0–5，定义见 `vocab.spicy_level` | 辣度 |
| 9 | `allergens` | string[] | ✅ | 取自 `vocab.allergens` 的 `name`，可为 `[]` | 过敏原大类 |
| 10 | `tags` | string[] | ✅ | 3–7 项，取自 `vocab.tags` | 规则引擎的唯一依据 |
| 11 | `reference_price` | int | ✅ | 8–198，单位元 | 该菜在城市普通餐馆的常见堂食价 |

> **一个字段都不多加。** 数据来源、校验人、校验时间等溯源信息放 `dish_source.json`，以 `id` 为键，保持 `dish` 对象干净。
> A 的视觉模型 prompt 就按这 11 个字段输出；B 的卡片也只读这 11 个字段。
> 拼音检索、别名、热度等衍生信息另放 `dish_search_index.json`，属于可选增强，不进主对象。

### 2.1 与方案文档 4.1 的差异说明

方案文档示例中 `id` 形如 `dish_sichuan_001`。落地时改为**按城市编号**（`dish_chengdu_01`），原因：

- 地域库是"城市 → 菜"的两级结构，按城市编号，id 自带归属信息，排查数据时不用回查；
- 一个菜系可能横跨多城（如川菜在成都、重庆都有），按菜系编号会产生归属歧义；
- 序号两位即可，250 条数据规模下没有溢出风险。

字段集合、语义、类型完全没变，**对 A/B 无影响**。

## 三、标签（`tags`）——规则引擎唯一读的东西

`tags` 不是装饰，是 M2 的输入。规则写成"标签 → 三色"，而不是"模型读食材再猜"，这样结果可复现、可解释、可审计。

标签共 33 个，分四组（完整定义见 `vocab.json.tags.definitions`）。每道菜 3–7 个：上限之所以放到 7，是因为像毛血旺这种菜同时含猪肉、禽肉、牛肉、内脏、加工肉，还要叠加高油与高嘌呤，6 个装不下事实。

| 组 | 标签 | 影响的规则 |
|---|---|---|
| risk 营养/加工风险 | 高油、油炸、高盐、腌制、高糖、精制碳水、高嘌呤、中嘌呤、高钾、高磷、加工肉、高蛋白 | 慢病限制、目标匹配 |
| meat 食材荤腥 | 含猪肉、含牛肉、含羊肉、含禽肉、含内脏、含海鲜、含蛋、含乳、含酒精、含咖啡因 | 宗教忌口、孕期、过敏兜底 |
| safety 入口安全 | 生食、半生食、高汞鱼 | 孕期、免疫低下、老人小孩 |
| form 形态 | 凉菜、汤羹、主食、小吃、甜品、火锅、烧烤、蒸菜 | 点菜组合的荤素/冷热/主食配额 |

**打标规则（写数据时逐条检查）：**

1. 食材里有猪肉/猪油/猪骨汤 → 必须 `含猪肉`；牛肉、羊肉、禽肉同理。
2. 有肝/腰/肚/肠/血/脑 → 必须 `含内脏` + `高嘌呤`。
3. 有蚝油、鱼露、虾皮 → 必须 `含海鲜`，并把对应过敏原（`mollusc`/`fish`/`crustacean`）写进 `allergens`。
4. 有酱油/豆瓣/豆豉 → `allergens` 必须含 `大豆`；酱油同时含 `含麸质谷物`。
5. 有料酒/黄酒/酒酿/啤酒且为凉菜、醉制、涮煮 → 必须 `含酒精` + `allergens: ["酒精"]`；红烧炖煮类料酒基本挥发，可不标 `含酒精`，但**必须标 `allergens` 吗？——不标**，在 `note` 里说明即可。判定口径：**入口酒精残留可感知或超过 0.5% 才标**，宁少不多，避免把整本菜单标成"别点"。
6. 辣度 ≥3 → 必须有 `辣` 或 `香辣` 或 `酸辣` 中的口味标签。
7. `生食`/`半生食` 只给真正生食的菜（刺身、生腌、溏心蛋、醉虾），不给"凉拌黄瓜"这类熟制后冷却的菜。

## 四、过敏原（`allergens`）

12 个大类，前 8 类对齐 GB 7718-2011 附录 C，后 4 类为项目扩展（见 `vocab.json.allergens`）。

**关键取舍：`allergens` 标的是"这道菜里存在哪一大类"，不是"哪个食材"。**
食材→大类的映射由 `03_禁忌库/ingredient_allergen_map.json` 维护，用途有两个：

1. 用户手动改食材（M1 的"可编辑修正"）后，前端/后端重新推导过敏原，不必重跑视觉模型；
2. 校验地域库：`ingredients` 里出现"虾皮"但 `allergens` 没有 `甲壳类`，直接判数据错误。

## 五、校验规则（`07_工具/validate.mjs` 实现）

| 级别 | 规则 |
|---|---|
| error | 12 字段齐全、类型正确、`id` 唯一、`region`/`city` 与 `vocab.cities` 一致、枚举值越界、`ingredients` <4 项、`tags` <3 项、`spicy_level` 越界、`reference_price` 越界 |
| error | 食材含"猪/牛/羊/鸡/鸭/鹅/鱼/虾/蟹/蚝/贝/鱿/蛋/奶/芝士/黄油/花生/芝麻/豆腐/酱油/豆瓣/酒"等词，但对应 tag 或 allergen 缺失 |
| warn | 菜名与 `ingredients` 无任何交集、`flavors` 与辣度矛盾（如 `辣` 口味但 `spicy_level=0`）、`reference_price` 同城离群（±2.5σ）、同城重名 |

> 校验脚本不是核心代码，属于 C 的交付工具，可被 A 接进 CI（`node 07_工具/validate.mjs`，退出码非 0 即失败）。

## 六、标准样例（可直接给 A 当 prompt few-shot）

```json
{
  "id": "dish_chengdu_01",
  "name": "干锅花菜",
  "region": "川菜",
  "city": "成都",
  "ingredients": ["花菜", "五花肉", "干辣椒", "花椒", "豆豉", "蒜苗"],
  "method": "干锅",
  "flavors": ["辣", "咸香"],
  "spicy_level": 2,
  "allergens": ["大豆"],
  "tags": ["高油", "高盐", "含猪肉"],
  "reference_price": 38
}
```

```json
{
  "id": "dish_chaozhou_04",
  "name": "生腌血蚶",
  "region": "潮州菜",
  "city": "潮州",
  "ingredients": ["血蚶", "蒜", "辣椒", "香菜", "鱼露", "米醋"],
  "method": "腌",
  "flavors": ["咸鲜", "辣"],
  "spicy_level": 1,
  "allergens": ["贝类", "鱼类"],
  "tags": ["生食", "含海鲜", "高盐", "凉菜"],
  "reference_price": 48
}
```

> 第二个样例特意选了"高风险菜"：`生食` + `高盐` + 两类过敏原，能一次触发孕期、过敏、慢病三条规则。给模型看正例，也要看这种"该标红的菜"。

## 七、字段与下游模块的对应

| 字段 | M1 视觉识别 | M2 健康规则 | M3 城市列表 | M5 语言视角 | M6 复刻视角 |
|---|---|---|---|---|---|
| `id` / `name` / `city` / `region` | ✅ 输出 | 引用 | ✅ 列表 | ✅ | ✅ |
| `ingredients` | ✅ 可编辑 | 兜底匹配 | — | 提及主料 | ✅ 采购清单 |
| `method` | ✅ | 判断油/盐/嘌呤 | — | 点菜话术 | ✅ 步骤 |
| `flavors` / `spicy_level` | ✅ | 忌口匹配 | 排序 | 口味解释 | 调味调整 |
| `allergens` | ✅ | **硬拦截** | ✅ 红标 | — | 替代建议 |
| `tags` | ✅ | **三色分级** | ✅ 筛选 | — | 难度/耗时 |
| `reference_price` | 可空 | — | ✅ 展示 | — | — |

**注意：`reference_price` 在 M1 拍照场景下允许为 `null`**（菜单上没标价），此时 B 的前端显示"—"。地域库侧一律必填。
