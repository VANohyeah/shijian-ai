# 地域菜库 · 使用说明

> 250 道 / 30 城 / 11 字段。这是 M3（地域推荐）的全部数据来源，也是 M2 的输入。

---

## 一、文件

| 文件 | 内容 | 消费方 |
|---|---|---|
| `dishes.json` | 250 道菜品，`{ version, count, dishes[] }` | A（接口）、B（列表与详情） |
| `cities.json` | 30 个城市：省份、大区、菜系、辣度基线、简介、`dish_count` | B（城市列表页）、A（`/api/city/:id`） |
| `dish_source.json` | 每道菜的溯源：生成方式、是否通过校验、自动补全记录、是否人工抽检 | 答辩举证，不参与业务 |
| `城市清单.md` | 城市分布、形态分布、过敏原分布、价格与辣度区间（脚本生成） | 文档写作 |
| `parts/g1–g6.json` | LLM 初稿原样保留（6 组并行生成） | 只读存档，证明"数据是生产出来的" |

---

## 二、怎么读

```js
// 城市列表
const cities = (await import('./cities.json')).default.cities;
// 按大区分组（华北/东北/华东/华中/华南/西南/西北）
const grouped = Object.groupBy(cities, c => c.area);

// 某城的菜
const dishes = (await import('./dishes.json')).default.dishes.filter(d => d.city === '成都');
```

字段语义见 `01_数据规格/菜品对象字段规范.md`。要点复述：

- `tags` 是规则引擎唯一读取的字段（33 个受控值，分风险/荤腥/安全/形态四组）；
- `allergens` 是过敏硬拦截的输入（12 类，前 8 类对齐 GB 7718）；
- `spicy_level` 按"不常吃辣的人"的体感标，不看辣椒用量；
- `reference_price` 是普通餐馆堂食价，只作参考，不做价格计算。

## 三、数据长什么样

**普通菜（无过敏原）**

```json
{
  "id": "dish_lanzhou_02",
  "name": "手抓羊肉",
  "region": "陇菜",
  "city": "兰州",
  "ingredients": ["羊肉", "花椒", "生姜", "大蒜", "盐", "香菜"],
  "method": "煮",
  "flavors": ["咸鲜"],
  "spicy_level": 0,
  "allergens": [],
  "tags": ["含羊肉", "高蛋白", "高盐"],
  "reference_price": 88
}
```

**高风险菜（生食 + 过敏 + 酒精）**

```json
{
  "id": "dish_chaozhou_03",
  "name": "生腌虾",
  "region": "潮州菜",
  "city": "潮州",
  "ingredients": ["基围虾", "蒜", "辣椒", "香菜", "鱼露", "高度白酒", "米醋"],
  "method": "腌",
  "flavors": ["咸鲜", "辣"],
  "spicy_level": 1,
  "allergens": ["甲壳类", "鱼类", "酒精"],
  "tags": ["生食", "含海鲜", "高盐", "含酒精", "凉菜"],
  "reference_price": 58
}
```

这两条放在一起看，就能理解为什么标签要分四组：前者触发「宗教/素食」与「痛风」，后者一次性触发「过敏 + 孕期 + 酒精」。

## 四、覆盖情况

- **城市**：七大区 30 城（华北 3 / 东北 2 / 华东 9 / 华中 3 / 华南 5 / 西南 5 / 西北 3）
- **每城 8–9 道**，优选能体现地域性的特色菜，不是全国通用家常菜
- **形态**：凉菜、汤羹、主食、小吃、甜品、火锅、烧烤、蒸菜均有覆盖
- **风险覆盖**：生食 4 道（顺德鱼生、潮州生腌血蚶、生腌虾等），含内脏 20+，含酒精 20+
- **语言视角**：250 条，与菜品一一对应

详细统计见 `城市清单.md`（可重跑刷新）。

## 五、怎么改

**只改一条菜**：改 `dishes.json` 对应记录 → 跑 `node 07_工具/build.mjs --check` → 通过即完成。**不要直接改 `parts/*.json`**，那是初稿存档。

**加一座城市**：在 `01_数据规格/vocab.json` 的 `cities` 里加一条（id/name/province/area/region/dish_target）→ 在 `parts/` 新增一组初稿 → 跑 `build.mjs` 生成。

**加一道菜**：id 规则 `dish_<city_id>_<序号>`，序号在该城连续；`region`/`city` 必须与 `vocab.cities` 一致；跑构建脚本会自动校验 20 多项。

## 六、已知局限

1. 价格是常见堂食价，城市内部差异大；
2. 250 道是"特色菜"不是"全菜单"，用户拍到的菜大概率不在库内（走 M1 实时识别）；
3. 地域归属按"最具代表性的城市"单一归属（如锅包肉归哈尔滨），不做多归属；
4. 复合调味料成分不可见，只能提示"可能含多种致敏物质"；
5. 现有 35 条 warn 均为风险标签建议（如"有酸菜未标腌制"），不影响三色判定，暂不清理。
