# 内容库 · 语言视角与复刻视角

> 两个视角的文案与菜谱。都是「菜品对象」的下游内容，以 `dish_id` 关联，不改变菜品本身。

---

## 一、文件

| 文件 | 内容 | 规模 | 页面 |
|---|---|---|---|
| `language_view.json` | 每道菜三段文案：是什么 / 怎么点 / 文化背景 | 250 条 | `/dish/[id]` 语言视角 Tab |
| `recipe_view.json` | 25 道家常菜谱：用料（带用量）、步骤、替代方案、要点 | 25 条 | `/dish/[id]` 复刻视角 Tab |

## 二、语言视角（M5）

### 2.1 字段

```json
{
  "dish_id": "dish_chaozhou_04",
  "what_it_is": "潮州街头名小吃，用新鲜珠蚝拌番薯粉浆，下猪油煎到边缘焦脆、中心软糯，配鱼露和香菜吃。",
  "how_to_order": "点的时候可以说：蚝烙要现煎的，鱼露另放；如果同行有人对贝类或蛋过敏，这份就不要点了。",
  "culture": "潮汕人把蚝烙当下午茶，讲究\"外脆内嫩\"，火候差十秒口感就不对，所以老店都是现点现煎。"
}
```

| 字段 | 要求 | 长度 |
|---|---|---|
| `what_it_is` | 是什么菜、什么味型、怎么吃。让人读完能在菜单上认出它 | 40–70 字 |
| `how_to_order` | 一句能直接对店员说的话，尽量包含对过敏/忌口人群有用的问法 | 30–60 字 |
| `culture` | 背景或吃法讲究，给"来了就该这么吃"的理由 | 30–80 字 |

### 2.2 写作规则

1. **不写空话**："深受当地人喜爱""味道鲜美"一律不要，这是最容易被评委看穿的地方；
2. **说人话**：可以出现"焦脆""软糯""冲鼻"这类感官词，但不要堆砌形容词；
3. **点菜话术要能照着念**：写"这个放蚝油吗""辣椒能另放吗"，而不是"建议询问店员配料"；
4. **不重复菜名**：`what_it_is` 里不要再把菜名念一遍；
5. **文化背景只写一句半**：讲一个具体的点（火候、时令、吃法顺序），不要写成百度百科。

### 2.3 前端渲染建议

- 语言视角用"释义段 + 话术气泡 + 背景小字"三段式，话术用引号包裹并加复制按钮；
- `how_to_order` 是给用户"照着念"的，字号要比正文大一号；
- 不要把三段揉成一段大文本，用户不会读。

## 三、复刻视角（M6，P2 可砍）

### 3.1 字段

```json
{
  "id": "rcp_01",
  "dish_id": "dish_chengdu_01",
  "name": "麻婆豆腐",
  "difficulty": "简单",
  "time_min": 20,
  "serves": 2,
  "ingredients": [{ "name": "嫩豆腐", "amount": "400g" }],
  "steps": ["……"],
  "substitutions": [
    { "from": "郫县豆瓣", "to": "无麸质豆瓣酱 + 少许味噌", "for": "大豆/麸质过敏", "note": "风味会淡一点，可用香菇粉补鲜" }
  ],
  "tips": ["……"],
  "allergen_note": "原菜含大豆、含麸质谷物；按上面的替代后可去掉其中一项。"
}
```

### 3.2 为什么替代方案比菜谱本身更重要

复刻视角的价值不只是"教你做"，而是"教你在限制下也能做"。因此 `substitutions` 必须覆盖**过敏原替代**，而不只是"买不到"：

| 原配料 | 替代 | 对应人群 |
|---|---|---|
| 酱油 / 豆瓣酱 | 无麸质酱油、椰子氨基酸 | 大豆、麸质过敏 |
| 蚝油 | 素蚝油、生抽+糖 | 贝类过敏 |
| 料酒 / 黄酒 / 啤酒 | 姜葱水、无醇料酒 | 酒精忌口、孕期、服药 |
| 花生油 / 花生碎 | 菜籽油、烤黄豆、南瓜籽 | 花生过敏 |
| 蛋清挂糊 / 鸡蛋 | 水淀粉、琼脂 | 蛋类过敏 |
| 牛奶 / 黄油 / 淡奶油 | 豆奶、椰子油、椰浆 | 乳制品过敏 |
| 面粉 / 薄脆 | 米粉、荞麦粉、无麸质粉 | 麸质过敏 |
| 芝麻酱 / 香油 | 南瓜籽酱、菜籽油 | 芝麻过敏 |
| 沙茶酱 | 自制素沙茶 | 甲壳类、鱼类过敏 |

### 3.3 与菜品表的关系

- `dish_id` 必须存在于 `dishes.json`，`name` 必须与菜品表逐字一致（`build.mjs` 会校验）；
- 菜谱里写的原配料，应当与 `dishes.json` 的 `ingredients` 大体重合；不一致时以菜谱为准（菜谱是"怎么做"，菜品表是"这道菜有什么"）；
- 25 道只覆盖家常可复刻的菜，**生食、宴席大菜、纯刀工菜不写菜谱**——写了也没人复刻，反而显得敷衍。

## 四、重新生成

两个文件都是独立数据，不参与 `build.mjs` 的 dishes 构建，但会被其一致性检查（`dish_id` 是否存在、菜名是否一致、步骤是否 ≥4、替代是否缺失）。改完跑一遍：

```bash
node 07_工具/build.mjs
```
