## 二、已知业务缺陷（不修，或本版修不了）

### 2.1 M6 复刻视角（最需要说清楚的一项）

1. **替代方案是人工编写的，不是实测配方**。它解决「缺料/过敏时怎么换」，但换了之后的风味、口感、成功率都没验证过；
2. 个别替代会明显改变风味（如用辣椒酱+盐代替郫县豆瓣），文案里已注明，但不能当作「一样好吃」；
3. **不能作为过敏人群的绝对安全指引**：真正的安全边界由 `allergens` 与规则决定，菜谱只做参考；
4. 25 道只覆盖家常可复刻的菜，生食、宴席大菜、纯刀工菜刻意不写——写了也没人复刻。

> 对应文档位置：技术文档 5.6 第 6 条；6.3 表格「复刻」一行。
> 对应测试：7.2 已补 2 条 M6 用例（大豆过敏 × 麻婆豆腐、服头孢 × 大盘鸡）。

## 三、给 A 的接入提醒（重要）

1. **必须复用同一套校验**：M1 的模型输出先跑 `node 07_工具/build.mjs --dish out.json`，error 非 0 就向前端返回「识别结果异常，请手动修正」，不要直接入库；
2. **过敏必须早返回**：`evaluate()` 里过敏命中直接 return forbid，不要塞进 hits 再取 max；
3. **`ingredients_any` 要处理单字与排除表**：`鸡毛菜` 不能命中禽肉，`啤酒花` 不能命中酒精；
4. **药物交互不进三色**：单独渲染提示条，否则没吃药的用户会被误标红；
5. **`dish_source.json` 不要丢**：里面 50 条 `human_reviewed:true` 是参赛要求的数据生产证据。
