## 二、集成验收（A/B 接入时逐项验）

### 2.1 字段契约

- [ ] A 的视觉模型 prompt 输出的 JSON，能直接通过 `build.mjs` 的字段校验（**用 `node 07_工具/build.mjs --dish out.json` 跑单条校验**，不要另写一套）
- [ ] 单条校验 error 非 0 时，前端显示「识别结果异常，请手动修正」，而不是静默入库
- [ ] B 的菜品卡组件只读 11 个字段，没有额外依赖
- [ ] 用户手动修改 `ingredients` 后，能调用食材映射表重算 `allergens` 与荤腥标签，不需要重跑模型
- [ ] 枚举越界（模型造词）时，前端有降级展示，而不是白屏

### 2.2 规则引擎

- [ ] `evaluate()` 在无网络环境下可运行（纯函数）
- [ ] 过敏命中直接返回 forbid，不被孕期/慢病规则覆盖（写一条单测）
- [ ] 规则命中顺序符合「过敏 > 孕期 > 忌口 > 慢病 > 目标」
- [ ] 每条命中都带得出 `evidence` id，前端依据浮层能显示知识条目标题与正文

### 2.3 页面

- [ ] `/city/[id]` 列表页每张卡默认显示三色标记（不需要用户点击"评估"）
- [ ] `/dish/[id]` 三视角 Tab 切换不重新请求
- [ ] 每张卡片底部有免责声明
- [ ] 加载态、空态、错误态都有（不复用"暂无数据"一句话敷衍）
- [ ] 移动端 375px 宽无横向滚动

### 2.4 兜底

- [ ] 模型超时 8s 后自动降级为手动输入菜名
- [ ] 知识库无命中时输出固定话术，不编造
- [ ] 城市无数据时提示附近城市，而不是空列表
