## 0. 一页速览

| 项 | 内容 |
|---|---|
| 技术栈 | Nuxt 3 + Vue 3 + TypeScript + SQLite（Drizzle ORM）+ Tailwind CSS4 |
| 模型 | 智谱 `glm-5.3-flash`（原生多模态，支持图片 + 工具调用 + 结构化输出） |
| 接口 | `https://open.bigmodel.cn/api/paas/v4`（OpenAI 兼容，直接用 `openai` SDK） |
| 运行 | **纯本地**，`npm run dev` 起在 `http://localhost:3000` |
| 演示 | 手机连同一 WiFi，访问 `http://<电脑局域网IP>:3000` |
| 数据 | 30 城 × 8–10 道菜 ≈ 250 道 + 400 条禁忌知识 |
| 交付 | GitHub 公开仓库 + 1080p 演示视频（5–8 分钟）+ ≤30 页 PDF |

**开发原则：契约先行 → 竖向切片 → 每天可见。**

## 3. 数据模型（唯一真源：`shared/types.ts`）

### 3.1 菜品对象

```ts
export type Allergen =
  | 'shellfish' | 'fish' | 'peanut' | 'tree_nut'
  | 'dairy' | 'gluten' | 'egg' | 'soy' | 'sesame'

export type DishTag =
  | 'high_oil' | 'high_salt' | 'high_sugar' | 'high_purine'
  | 'raw' | 'alcohol' | 'pork' | 'beef' | 'high_mercury' | 'high_protein'

export interface Dish {
  id: string                 // dish_<城市拼音>_<序号>，如 dish_chengdu_003
  name: string
  city: string               // 成都
  region: string             // 川菜
  ingredients: string[]      // ['花菜','五花肉','干辣椒','花椒','豆豉']
  method: string             // 干锅 / 清蒸 / 红烧 …
  flavors: string[]          // ['辣','咸香']
  spicyLevel: 0 | 1 | 2 | 3  // 0 不辣 1 微辣 2 中辣 3 特辣
  allergens: Allergen[]
  tags: DishTag[]
  referencePrice: number     // 元
  description: string        // 一句话：这是什么菜
  recipe?: {
    steps: string[]
    subs: { from: string; to: string; reason: string }[]
  }
}
```

**为什么 allergens / tags 用英文枚举**：求交集、做规则判断都靠它。展示时查 `LABELS` 映射表转中文，绝不把中文写进逻辑。

### 3.2 用户档案

```ts
export interface Profile {
  gender: 'male' | 'female'
  age: number                  // 10–100
  heightCm: number             // 100–220
  weightKg: number             // 25–200
  activity: 'sedentary' | 'light' | 'moderate' | 'active'
  goal: 'fat_loss' | 'muscle_gain' | 'sugar_control' | 'purine_control' | 'none'
  allergens: Allergen[]
  conditions: ('hypertension' | 'diabetes' | 'hyperuricemia' | 'ckd')[]
  dietary: ('vegetarian' | 'vegan' | 'halal' | 'no_alcohol' | 'pregnant')[]
}
```

BMI / BMR **前端算**，不进模型上下文。

### 3.3 评估结果

```ts
export type Level = 'safe' | 'caution' | 'avoid'

export interface Reason {
  type: 'allergen' | 'condition' | 'pregnancy' | 'dietary' | 'goal'
  severity: 'hard' | 'soft'
  text: string          // 人话，直接给用户看
  evidence?: string     // 依据标题，如「八大类过敏原清单」
}

export interface Citation {
  id: string
  title: string
  snippet: string
  source: string
}

export interface TraceStep {
  tool: string
  args: unknown
  result: unknown
}

export interface Evaluation {
  level: Level
  summary: string          // 一句话结论
  reasons: Reason[]
  citations: Citation[]
  trace: TraceStep[]       // 给评委看的调用链
}
```

### 3.4 知识条目

```ts
export interface Knowledge {
  id: string
  category: 'allergen' | 'condition' | 'pregnancy' | 'drug' | 'goal'
  keywords: string[]       // ['痛风','嘌呤','高尿酸']
  title: string
  content: string          // 100 字以内
  source: string           // 依据出处，必填
  severity: 'hard' | 'soft'
  blocks?: DishTag[]       // 命中即禁的 tag，如 ['high_purine']
}
```

### 3.5 数据库表

```ts
users(id, username, email, password_hash, profile_json, created_at)
dishes(id, city, region, name, data_json)      // data_json 存完整 Dish
knowledge(id, category, keywords, title, content, source, severity, blocks)
cities(id, name, province, dish_count)
scans(id, user_id, dish_json, evaluation_json, created_at)
```

菜品/知识用 JSON 列存正文，字段索引只留查询用的——**10 天项目，别做过度规范化**，评委也不会因为 JSON 列扣分。

## 4. 接口契约（`docs/api.md` 与本表同步）

### 4.1 统一约定

- 成功：`200` + 直接返回数据
- 失败：`4xx/5xx` + `{ "error": { "code": "UNAUTHORIZED", "message": "请先登录" } }`
- 认证：`Cookie: sid=<HMAC 签名串>`，`HttpOnly`、`SameSite=Lax`
- 时间统一 ISO 字符串；金额单位元

### 4.2 认证

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/auth/register` | `{username, email, password}` | `{user:{id,username,email}, profile:null}` |
| POST | `/api/auth/login` | `{username, password}` | `{user, profile}` + Set-Cookie |
| POST | `/api/auth/logout` | — | `{ok:true}` |
| GET | `/api/auth/me` | — | `{user, profile}` 或 401 |
| PUT | `/api/profile` | `Profile` | `{profile}` |

密码：`bcryptjs` cost 10；用户名 3–20 位；密码 ≥ 8 位。

### 4.3 识别与评估

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/scan` | `{image: "data:image/jpeg;base64,..."}` | `{dish: Dish, confidence: number, warnings: string[]}` |
| POST | `/api/evaluate` | `{dish: Dish}` | `Evaluation` |

`scan` 内部：压缩 → 调 `glm-5.3-flash` → 严格 JSON → Zod 校验 → 失败重试 1 次 → 仍失败则返回 `confidence:0` + 提示手动输入。

`evaluate` 内部：规则引擎（代码判定）→ 检索依据 → 模型写解释 → 合并输出。

### 4.4 地域与组合

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/cities` | — | `[{id,name,province,dishCount}]` |
| GET | `/api/cities/:id/dishes` | — | `[{dish, evaluation}]` |
| GET | `/api/dishes/:id` | — | `{dish}` |
| POST | `/api/plan` | `{cityId, people, budget, dishIds[]}` | `{picks:[{dish,evaluation}], total, risks:Reason[], swaps:[]}` |

## 5. 核心逻辑

### 5.1 规则引擎（`server/utils/rules.ts`，**纯函数**）

判定必须由代码算，模型只负责解释。这是「AI 安全 4%」的底牌。

```ts
export function evaluateRules(dish: Dish, p: Profile): Evaluation
```

优先级（高 → 低）：

| 顺序 | 规则 | 结果 |
|---|---|---|
| 1 | `dish.allergens ∩ p.allergens ≠ ∅` | **avoid（硬）**，不允许降级 |
| 2 | `p.dietary.includes('pregnant')` 且 `tags ∩ [raw, alcohol, high_mercury]` | **avoid** |
| 3 | `halal` + `pork` ／ `no_alcohol` + `alcohol` | **avoid** |
| 4 | `hyperuricemia` + `high_purine` | avoid（重度）/ caution |
| 5 | `hypertension` + `high_salt` ／ `diabetes` + `high_sugar` | caution |
| 6 | `fat_loss` + `[high_oil, high_sugar]` | caution（软） |
| 7 | `muscle_gain` + `high_protein` | safe + 正向提示 |
| 8 | 无命中 | safe |

返回时每条 reason 带 `evidence`（依据标题）。**没把握就返回 `caution` 并写「不确定，建议询问店员」，禁止编造。**

### 5.2 检索（`server/utils/retrieve.ts`）

不用 FTS5（中文分词会坑），用：

```
关键词倒排：knowledge.keywords 建 Map<词, Knowledge[]>
同义词：synonyms.json，如「痛风 → 高尿酸、嘌呤」
打分：命中词数 × 2 + 标题命中 × 3 + category 匹配 × 1
返回 top 3
```

400 条数据，内存 Map 就够，不用建表。

### 5.3 模型调用（`server/utils/ai.ts`）

```ts
import OpenAI from 'openai'

const ai = new OpenAI({
  apiKey: process.env.ZHIPU_API_KEY,
  baseURL: 'https://open.bigmodel.cn/api/paas/v4',
})

// 视觉识别
await ai.chat.completions.create({
  model: 'glm-5.3-flash',
  temperature: 0.2,
  messages: [{
    role: 'user',
    content: [
      { type: 'text', text: SCAN_PROMPT },
      { type: 'image_url', image_url: { url: dataUrl } },
    ],
  }],
})
```

**坑**：
- `thinking.type` 只能 `enabled`，**关不掉** → 响应可能 5–15 秒，前端必须给进度提示
- 官方推荐 `temperature: 1`；结构化抽取先用 0.2，若 JSON 不稳再回 1
- 单次请求图片 base64 别超 4 MB；前端压到长边 1600px、quality 0.8
- 超时设 30s，失败重试 1 次

### 5.4 scan 的 Prompt 要点

```
你是菜品识别助手。只输出 JSON，不要解释，不要 markdown 代码块。
字段缺失填 null，禁止编造。ingredients 只写能看见或能合理推断的。
allergens 只能从这 9 个里选：shellfish, fish, peanut, tree_nut, dairy, gluten, egg, soy, sesame
tags 只能从这 11 个里选：high_oil, high_salt, high_sugar, high_purine, raw, alcohol, pork, beef, high_mercury, high_protein
不确定时 confidence 给低分。
{schema}
```

### 5.5 Agent 编排（`server/api/evaluate.post.ts`）

四条工具：`get_user_profile` / `match_restrictions` / `search_knowledge` / `explain`。

**不要写死顺序**：把工具交给模型（function calling），让它自己决定先查哪个、要不要重试。同时在服务端记录每一步进 `trace`，直接展示给评委看。

兜底：模型 3 轮内没收敛 → 用确定性结果 + 模板化文案返回，**绝不让用户看到报错页**。

## 9. 已知的坑（提前写下来，别踩第二次）

| 坑 | 症状 | 解法 |
|---|---|---|
| better-sqlite3 原生模块 | Nitro 报 `Cannot find module` | `nuxt.config.ts` 里 `nitro.externals.external: ['better-sqlite3']`；装不上就换 Prisma |
| OneDrive 锁 db | `SQLITE_BUSY` / `.db-wal` 同步冲突 | 暂停 OneDrive 该目录同步，或把 `data/` 移出 OneDrive |
| 智谱 thinking 关不掉 | 接口慢，以为卡死 | 前端给进度提示，按钮 loading，别重复点 |
| base64 太大 | 413 / 请求超时 | 前端压到 1600px、0.8 质量 |
| 模型返回带 ```json | JSON.parse 失败 | 剥掉 code fence 再 parse，并加重试 |
| 中文分词 | FTS5 查不到「痛风」 | 不用 FTS5，用关键词 Map |
| 手机访问不到 | 局域网 IP 打不开 | 防火墙放行 3000；`host: '0.0.0.0'` |
| Tailwind 4 配置 | 样式全不生效 | 用 `@tailwindcss/vite` 插件 + `@import "tailwindcss"` |
